## P1 — retained exact rows and off-grid source law are not identity-bound

`SourceMotionQuery.__init__` retains `plan`, `locomotion_gait`, `solver_gait`, `transition`, and source-derived body height independently (`source_motion_query.py:153-188`). It never proves that the plan was generated by those profiles at that height. Exact keys use retained rows, while adjacent values resample the independently supplied gait at `context.body_height` (`source_motion_query.py:216-222`). This permits a discontinuous object that still reports `AVAILABLE` and can report a converged derivative away from the retained keys.

Concrete reproductions:

- A plan authored at body height `2.0 m` is accepted with the fixture's source-derived `1.6 m`. At `t=0.041025641025641026`, exact and `nextafter(t,+inf)` root travel are `0.020512820512820513 m` and `0.016410256410256417 m`; the maximum local-translation jump is `10.041170846442293 mm` over one representable float step.
- A plan authored with step length `0.2 BH` is accepted with a query gait of `0.4 BH`. At `t=0.41025641025641024`, exact and nextafter root travel are `0.16410256410256413 m` and `0.3282051282051283 m`, a `164.10256410256419 mm` pose jump.

The constructor needs a canonical plan/profile/source-law binding: exact program/schema, exact body height, gait parameter payload, transition payload, and the compiler-derived solver contract. Reject mismatches before retaining the query.

## P1 — contact event sides are inferred from sampled rows, not the authored event law

Lines 189-196 register the first sampled row after a contact boolean changes as the boundary. For a 24 Hz grounded fixture (`step_period=0.8 s`, `duty=0.72`), the actual right liftoff is `0.352 s`, but the query registers `0.36923076923076925 s`. `_is_boundary(0.352)` is false. `evaluate(0.352, side=left_limit|value|right_limit)` returns the same `[left=True,right=False]` contact assignment for all three; one-ULP `nextafter` does not survive the phase arithmetic as a canonical event side. All three derivative requests return `BRANCH_OR_CONVERGENCE_UNAVAILABLE`, so the API cannot obtain either declared one-sided derivative at the real event.

Derive event times and canonical side semantics from the bound sampler/choreography law. A requested one-sided derivative must evaluate a side-owned boundary value and probes wholly inside that side; using `center = evaluate(time)` at line 386 anchors both directions to the ordinary event value.

## P1 — optional material witnesses ignore the contact profile's source binding

Lines 186-188 construct `SkinRig` without validating `contact_profile.source.sha256` against the retained source provenance. The committed production test itself passes historical source `044a8be...` with contact profile v10 bound to recovered source `2cdd901...`; the query accepts it and emits 1,564 left and 1,417 right material points. Compatible accessor numbers do not establish calibrated material correspondence. This invalidates the meaning of optional FK/LBS material witnesses and their derivatives.

Validate the exact declared source binding before admitting the contact profile. The existing factory pattern can use the original `source.raw` provenance so a supported uniform in-memory scale does not masquerade as a different source.

## P2 — malformed constructor inputs escape the query contract

The shallow plan check at lines 157-158 accepts `{"samples":[{},{}]}` and nonnumeric row times; line 177 then raises raw `KeyError` and `ValueError`. `legacy_overlay="false"` is also accepted and silently coerced to `True` at line 170. These are public query inputs and should fail as `ContractError` with strict primitive types before retained state is built.
